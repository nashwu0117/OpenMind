# Security policy

[English](SECURITY.md) · [繁體中文](SECURITY.zh-TW.md)

When stable 0.3.x releases are published, only the latest release will be supported; preview builds are not stable releases. To report a vulnerability privately, use this repository's **Security and quality → Advisories → Report a vulnerability** form. Do not open a public issue for an undisclosed vulnerability. Include the affected version and a minimal reproduction, and remove private mind maps, attachments, credentials and local file paths from the report.

Threat boundaries: untrusted .openmind/Markdown/OPML/FreeMind text, raster images, binary attachments, limited TeX, hyperlinks, IndexedDB/recovery and sandboxed renderer IPC. Import limits and strict fields prevent silent loss; attachments are downloadable bytes, not executed. FreeMind XML now has a 2 MB input cap, 50,000-element and 256-level structural caps, plus a single bounded validation traversal. Browser tabs use a Web Lock for one writer; other tabs stay read-only and reload the latest local document when the writer closes. Electron prevents a second application process and focuses the existing window. Unsupported browser lock APIs fail closed to read-only. TeX excludes external package/HTML commands. All native destinations come from user dialogs. Core editing/export/printing use local resources; no telemetry or automatic document upload. Package downloads happen during development setup. macOS updates require user-initiated network access and never include document content; see `docs/RELEASING.md`.

Native printing uses a private temporary directory containing a mode-0600 HTML file, with embedded font/image data and restrictive content policy. The file and hidden print window are removed after output or load failure. A process or OS crash can leave temporary files; avoid using public reports to share their contents.

The source review covered document validation and storage, parsing and exports, Electron IPC, printing and release automation. It is not a guarantee of security; run dependency audits and tests before releases and keep Electron patched. macOS signing, notarization, clean-machine installation and a real updater round trip still require release credentials and external testing. See `docs/RELEASING.md` for the release controls and current validation limits.
